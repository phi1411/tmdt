==================================================
3. BACKEND ARCHITECTURE
==================================================

Sử dụng modular monolith.

Ưu tiên cấu trúc tương tự:

backend/
├── app/
│   ├── __init__.py
│   ├── config.py
│   │
│   ├── api/
│   ├── services/
│   ├── repositories/
│   ├── schemas/
│   ├── auth/
│   ├── db/
│   ├── errors/
│   └── utils/
│
├── tests/
├── requirements.txt
└── run.py hoặc entrypoint phù hợp

Có thể điều chỉnh nếu architecture docs đã quy định khác.

Không tạo abstraction thừa.

==================================================
4. APP FACTORY
==================================================

Dùng Flask Application Factory nếu phù hợp architecture hiện tại.

Backend phải hỗ trợ ít nhất:

- development
- testing

Không hardcode:

- MongoDB URI
- JWT secret
- VNPAY secrets
- environment-specific config

Đọc từ environment.

.env không commit.

.env.example phải có key name nhưng không chứa secret thật.

==================================================
5. MONGODB CONNECTION
==================================================

Dùng PyMongo.

Connection phải sử dụng database ecommerce_dev trong development theo config.

Replica set phải hoạt động.

Thiết kế connection lifecycle rõ ràng.

Có health check xác nhận:

- Flask running
- MongoDB reachable
- replica set usable

Không tạo một MongoClient mới cho mỗi request nếu không cần.

==================================================
6. LAYER RESPONSIBILITY
==================================================

API / Controller:

- nhận request
- parse input
- gọi service
- trả response

Không chứa business logic phức tạp.

Service:

- business rules
- orchestration
- transaction boundaries khi cần

Repository:

- MongoDB access
- query
- insert/update
- aggregation invocation khi phù hợp

Schema / Validation:

- request/response validation hoặc mapping theo strategy đã chọn

Không để frontend concern trong backend.

==================================================
7. OBJECTID HANDLING
==================================================

Tạo cách xử lý ObjectId thống nhất.

API JSON không được làm frontend nhận BSON ObjectId trực tiếp không serialize được.

Quy định rõ:

MongoDB:
ObjectId

API:
string

Không mỗi endpoint convert theo một kiểu khác nhau.

==================================================
8. API RESPONSE CONVENTION
==================================================

Khóa response format nhất quán.

Ví dụ thành công có thể theo:

{
  "data": ...
}

hoặc format đã được docs/api-conventions.md quy định.

Error phải có cấu trúc ổn định, ví dụ:

{
  "error": {
    "code": "...",
    "message": "...",
    "details": ...
  }
}

Không trả traceback cho client.

Không để endpoint mỗi nơi một kiểu.

10. GLOBAL ERROR HANDLING
==================================================

Chuẩn bị error hierarchy hoặc cơ chế tương đương:

Unexpected error phải được log.

Client không được thấy stack trace production-style.

==================================================
11. AUTH FOUNDATION
==================================================

Chưa cần implement full Auth feature.

Nhưng dựng foundation cho:

- JWT
- get current user
- role authorization
- CUSTOMER
- ADMIN

Password hashing hiện tại là Argon2id.

Không chuyển sang plain SHA/bcrypt nếu không có lý do.

Không duplicate authentication logic trong từng endpoint.

==================================================
12. REQUEST VALIDATION
==================================================

Chọn strategy rõ ràng và nhất quán cho request validation.

Có thể dùng library hợp lý nếu project chưa khóa.

Nhưng không thêm dependency nặng không cần thiết.

Phải hỗ trợ sau này:

- type validation
- required fields
- enum
- nested payload
- clear validation errors

MongoDB validator KHÔNG thay thế API input validation.

==================================================
13. PAGINATION CONTRACT
==================================================

Chuẩn bị convention cho list endpoint:

Ví dụ:

?page=
&limit=

Phải có:

- giới hạn maximum page size
- metadata response

Ví dụ:

{
  "data": [...],
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 180,
    "totalPages": 9
  }
}

Có thể theo convention docs hiện tại.
